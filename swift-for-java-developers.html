1. What this project is

A small iOS app for tracking personal goals. A user can:

  • Create a Goal with a title, a "why", and a colour (NewGoalView).
  • Break it into Subgoals and tick them off (SubgoalRow).
  • Run a timer to record FocusSessions (GoalDetailView).
  • Do a "reality check" — pause or release a goal that no longer matters (RealityCheckSheet).
  • View totals (GoalStatisticsView).

In backend terms, map it like this:

LayerJava backend analogyThis project
EntitiesJPA @Entity classesGoal, Subgoal, FocusSession in Goal.swift (SwiftData @Model)
PersistenceHibernate EntityManager / Spring DataModelContext + ModelContainer (SwiftData, backed by SQLite)
QueriesJPQL / @Query in Spring Data@Query + #Predicate
PresentationControllers + Thymeleaf/ReactSwiftUI View structs
Bootstrappublic static void main / @SpringBootApplication@main struct DreamTrackerApp: App
There is no server, no REST, no DI container. Everything runs on-device; data lives in a local SQLite database managed by SwiftData.

2. Compiled? Interpreted? Virtual machine?

Swift is compiled ahead-of-time (AOT) to native machine code. There is no JVM-like virtual machine and no interpreter in production.

Java pipeline

.java │ javac ▼ .class (bytecode) │ JVM: interpreter + JIT ▼ machine code (at runtime) + Garbage Collector + Class loading, reflection

Swift pipeline

.swift │ swiftc (frontend) ▼ SIL → LLVM IR │ LLVM backend (optimizer) ▼ native ARM64 binary (.app) runs directly on CPU + small Swift runtime (ARC, metadata)
QuestionJavaSwift
Compiled?To bytecodeTo native machine code (via LLVM)
Virtual machine?Yes, the JVMNo. There is a lightweight runtime library, not a VM
JIT?Yes (HotSpot)No JIT on iOS (the OS forbids it for apps). Optimization happens at build time
Garbage collector?YesNo — uses ARC (reference counting, inserted at compile time)
"Write once, run anywhere"?Yes (same bytecode)No — you compile per target platform (iOS, macOS, Linux...)
Build toolMaven / GradleXcode build system (xcodebuild), Swift Package Manager for libraries
Startup timeJVM warm-upInstant — it is just a native binary
REPL / scriptingjshellSwift can run as a script (swift file.swift) and Xcode Playgrounds/Previews use an incremental JIT, but shipped apps are native
Practical effect: compile errors catch a lot, performance is predictable (no GC pauses), and reflection is far more limited than in Java. That limitation is why SwiftData uses macros (@Model) — code generation at compile time — instead of runtime bytecode proxies like Hibernate does.

Java vs Swift: the same thing, side by side

Java

public enum GoalStatus {
    ACTIVE, PAUSED, RELEASED
}

@Entity
public final class Goal {
    @Id @GeneratedValue Long id;
    String title;
    String why;
    @Enumerated(STRING) GoalStatus status;

    @OneToMany(cascade = ALL, mappedBy = "goal")
    List<Subgoal> subgoals = new ArrayList<>();

    public Goal(String title, String why) {
        this.title = title;
        this.why = why;
        this.status = GoalStatus.ACTIVE;
    }
}

Swift (this project)

enum GoalStatus: String, Codable {
    case active, paused, released
}

@Model
final class Goal {
    var title: String
    var why: String
    var status: GoalStatus

    @Relationship(deleteRule: .cascade,
                  inverse: \Subgoal.goal)
    var subgoals: [Subgoal] = []

    init(title: String, why: String = "",
         status: GoalStatus = .active) {
        self.title = title
        self.why = why
        self.status = status
    }
}

Notice: no @Id (SwiftData adds a persistent identifier), no getters/setters (properties are first-class), default argument values replace constructor overloading, no new keyword when calling constructors (Goal(title: "x")).

4. Memory: ARC instead of a garbage collector

The compiler inserts retain / release calls automatically. Each class instance has a counter of strong references; when it hits zero the object is freed immediately and deterministically (deinit runs right then, unlike Java's unpredictable finalize).

  • Gotcha — retain cycles: if A strongly references B and B strongly references A, neither is freed. Swift solves this with weak and unowned references. In Java, the GC handles cycles for you.
  • In this project: Goal.subgoals ↔ Subgoal.goal look like a cycle, but SwiftData manages the object graph, so you don't hand-write weak here.

5. Value types vs reference types (the biggest mental shift)

class (reference)struct / enum (value)
AssignmentCopies the pointer (shared object), like all Java objectsCopies the data (independent copy)
InheritanceYes (single)No (but can conform to protocols)
MutationAlways allowed on var propertiesOnly if the instance is var (let struct is fully immutable)
Used here forGoal, Subgoal, FocusSession — entities with identityAll views (GoalsListView…), DreamTrackerApp, GoalColor, GoalStatus

Java only has "reference types" (objects) and "primitives". In Swift, String, Int, Array, Dictionary, Date are all structs (value types, copy-on-write for collections). The rule of thumb: use structs by default; use classes when you need identity or shared mutable state — which is exactly why database entities are classes and UI views are structs.

enum in Swift is far more powerful than in Java: cases can have associated values, computed properties, methods, and a String/Int raw type. See GoalColor, which has computed properties and a switch inside an enum.

6. Optionals & null safety

Swift has no null for normal types. A value that may be absent is an Optional (T?), like Java's Optional<T> but built into the language and enforced by the compiler everywhere.

var completedAt: Date?                // Subgoal.swift: may be nil
var goal: Goal?                       // back-reference, may be nil

guard let start = currentSessionStart else { return }   // unwrap or exit early
if isTimerRunning, let start = currentSessionStart { }  // unwrap in condition
try? modelContext.save()              // "try?" turns a thrown error into nil
SwiftJava equivalent
if let x = opt { … }opt.ifPresent(x -> …) / if (x != null)
guard let x = opt else { return }if (x == null) return; — and x stays unwrapped for the rest of the scope
opt ?? defaultValueopt.orElse(defaultValue)
opt?.method()no direct equivalent (optional chaining, short-circuits to nil)
opt!opt.get() — crashes if nil. Avoid

Errors: Swift has throws/try/catch but no checked-exception declarations in signatures beyond throws, and errors are values, not class hierarchies you extend from Exception. See NewGoalView.saveGoal() for do { try … } catch { … }.

Closures & trailing-closure syntax

If the last argument of a function is a closure, you can write it after the parentheses. This is why SwiftUI code looks like markup:

Button { isShowingNewGoal = true } label: { Image(systemName: "plus") }
//     └── action closure (trailing)       └── "label:" closure

sessions.reduce(0) { $0 + $1.duration }
// Java: sessions.stream().mapToDouble(Session::duration).sum()

8. Property wrappers & macros (the @ things)

In Java, annotations are metadata read via reflection at runtime. In Swift there are two distinct things sharing the @ sigil:

  • Property wrappers (@State, @Query, @Bindable, @Environment): they change how a property behaves — e.g. storing the value elsewhere and triggering UI refreshes.
  • Macros (@Model, #Predicate): compile-time code generators that expand into more Swift code. Closest Java analogue: annotation processors like Lombok / MapStruct — except the generated code is type-checked Swift.
AttributeWhat it doesAnalogyWhere
@mainEntry pointmain() / @SpringBootApplicationDreamTrackerApp
@ModelMacro. Makes a class observable and persistable by SwiftData; adds change tracking, persistent ID, and schema info@Entity + Hibernate dirty-checkingGoal, Subgoal, FocusSession
@Relationship(deleteRule:inverse:)Declares an association; .cascade deletes children with parent; inverse: points to the owning-side key path@OneToMany(cascade = REMOVE, mappedBy = …)Goal.subgoals, Goal.sessions
@QueryLive-fetches entities and auto-refreshes the view when the DB changesSpring Data @Query, but reactiveGoalsListView.activeGoals

@StateView-local mutable state owned by SwiftUI. Changing it re-renders bodyA mutable field in a stateful component; React useState@State private var title = ""
@BindableLets you create $bindings into properties of an @Observable/@Model object–@Bindable var goal: Goal → $goal.status

Why views are structs and still hold state

A SwiftUI view is a throw-away, lightweight description of the UI. SwiftUI re-creates these structs constantly. @State stores the value outside the struct (in SwiftUI's own storage), so it survives re-creation. When a @State value or an observed @Model property changes, SwiftUI calls body again and diffs the result — conceptually like React.

Bindings: $

title reads the value; $title is a Binding<String> — a getter/setter pair that a TextField uses to write back. There is no Java equivalent; think of it as passing a reference to the variable itself.

10. File-by-file walkthrough

DreamTrackerApp.swift — the bootstrap

@main
struct DreamTrackerApp: App {
    var body: some Scene {
        WindowGroup { GoalsListView() }
            .modelContainer(for: [Goal.self, Subgoal.self, FocusSession.self])
    }
}

Equivalent of main() + a Spring config class: shows the first screen and registers the DB schema. Goal.self is the type object (Goal.class in Java).

Goal.swift — the domain model

  • Goal 1—N Subgoal and 1—N FocusSession, both with .cascade delete (delete a goal → children removed).
  • Computed properties totalSeconds and formattedTotalTime are not stored; they're recalculated on every access (like a getter with no field).
  • FocusSession.duration = endedAt - startedAt.
  • final on @Model classes is required: SwiftData's generated code doesn't support subclasses.

GoalColor.swift — enum with behavior

UI-side enum mapping a color choice to a name, a SwiftUI Color and a hex string (the hex string is what's persisted in Goal.colorHex). It shows switch expressions: each case directly yields a value without return.

GoalsListView.swift — the home screen

  • @Query with #Predicate fetches only .active goals, sorted newest-first. The result array updates automatically as data changes.
  • The comment about activeStatus as a file-level private let: macros can't capture enum cases inside the predicate, so a constant is used.
  • @State isShowingNewGoal toggles the "new goal" sheet.
  • NavigationLink(value: goal) + .navigationDestination(for: Goal.self) routes to GoalDetailView.

GoalRow.swift — a list cell

A tiny stateless view that takes a let goal and shows title + total time. Like a pure presentational component.

NewGoalView.swift — the creation form

  • Local form state in @State (title, why, color, subgoal titles).
  • canSave is a computed property used to disable the Save button.
  • saveGoal(): trim input → create Goal → append Subgoals → modelContext.insert → save() → dismiss(). Similar to a service method with a transaction.
  • ForEach($subgoalTitles.indices, id: \.self) lets each row bind to $subgoalTitles[index].

GoalDetailView.swift — the main screen

  • @Bindable var goal enables $goal.status for the Picker — edits write straight into the model object.
  • The timer state (isTimerRunning, currentSessionStart) is purely UI state; only on Stop does it create and persist a FocusSession.
  • TimelineView(.periodic(from:by:)) ticks every second so the elapsed time label updates — no manual Timer/thread.
  • Private helper methods (startSession, stopSession, addSubgoal, deleteSubgoals, deleteGoal) act like service methods.
  • Deleting: modelContext.delete(goal) then dismiss() pops back to the list.

SubgoalRow.swift — editable row

Uses @Bindable so toggling isCompleted or editing the title mutates the @Model directly, and the UI updates through observation. Note the ternaries driving icon and colour.

RealityCheckSheet.swift — reflection dialog

A sheet that sets goal.status to .active, .paused or .released and optionally overwrites goal.why. Since the list queries only .active goals, pausing/releasing makes the goal vanish from the home list automatically — a nice illustration of reactive @Query.

GoalStatisticsView.swift — read-only report

Shows totals and the 10 most recent sessions using sorted { $0.startedAt > $1.startedAt }.prefix(10) (Java: stream().sorted(comparing(...).reversed()).limit(10)).

11. How data flows (the "semantics")

App launch └─ DreamTrackerApp creates ModelContainer (SQLite) and injects ModelContext └─ GoalsListView ├─ @Query ──────────► reads active Goals from the DB (live) ├─ "+" ─► sheet ─► NewGoalView ─► modelContext.insert(Goal) ─► save() │ │ │ @Query notices the change ◄───┘ → list re-renders └─ tap row ─► GoalDetailView(goal) ├─ @Bindable goal ─► edits mutate the model directly ├─ Start/Stop ─► @State timer ─► FocusSession appended ─► save() ├─ Subgoals ─► SubgoalRow (toggle/edit) ─► model changes ├─ Reality check sheet ─► goal.status = .paused / .released │ (goal leaves the active @Query) └─ Statistics ─► GoalStatisticsView (read-only)

The core idea is unidirectional, reactive data flow: state → view. You never imperatively say "update this label"; you mutate state and SwiftUI recomputes the affected bodys. In your Java world, imagine the controller never calls view.setText(...); instead, the view is a pure function render(state) that is re-run whenever state changes.

Two kinds of "state" here:
  • Ephemeral UI state → @State (form fields, timer, sheet flags). Lost when the view goes away.
  • Persistent domain state → @Model objects. Survives app restarts via SwiftData.
